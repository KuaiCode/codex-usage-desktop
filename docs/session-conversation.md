These are CLI/TUI and history replay references, not evidence of the desktop application's pixel layout.

This project's Rust replay remains responsible for event ordering, process polling and token updates. `src/lib/session-conversation.ts` adapts that replay into a cached conversation model and owns legacy tool argument/output decoding. It does not evaluate logged JavaScript. The React component renders messages, exploration and command activities from that model.

Namespaced function calls retain their qualified identity, with the default `functions` namespace omitted. `clock.sleep` renders as a collapsed waiting activity with the requested duration and the existing model token badge. Expansion retains the full response, including actual wall time, and raw JSONL. Rust merges `Extension(kind: "clock.sleep")` completion records into the same call by ID, including completion-only logs. Lifecycle completion alone means the wait ended; the function output distinguishes normal completion from interruption by new input. Missing completion remains incomplete, and explicit failures retain error styling. Same-named tools in other namespaces use the generic renderer. The CLI rebuilds a typed Sleep item but currently skips it in TUI replay; this waiting card is a desktop rendering choice.

Code-mode orchestration records several inner tools under one outer `exec` item. Rust replay first reads `item_completed` / `CommandExecution` records, which already contain the command, output and an independent execution ID. Repeated records update the same ID. Exact tool IDs update direct commands; an execution's recorded start time associates it with a uniquely enclosing outer script, even when its completion arrives during a later poll. Records without a provable parent remain independent activities at their original log position. Native command outputs take precedence over printed previews, retain their own failure state and raw records, and never receive a share of the outer call's tokens.

For older logs without command execution records, the projection scans calls outside quoted strings and comments. Literal sequential commands, terminal polls, patches and image views can become child activities only when every call is understood. Logged JavaScript is never evaluated. Call arguments must start at that call's argument boundary; an unresolved variable cannot borrow a later call's object.

Literal `Promise.allSettled` tool arrays and command tuples mapped through `exec_command` render as individual activities without the orchestration wrapper. Native command records supply the corresponding results regardless of print order. Without those records, source order alone does not prove output order: parallel process results are paired only with explicit indices. Unindexed parallel results remain independent numbered outputs. Other callbacks, loops, branches and mixed unsupported tools retain the complete outer script. Structured responses show stdout, stderr and process session; exit codes and execution durations are hidden, while failures retain their error styling. Sequential process results are paired only with explicit indices or a complete result set emitted immediately in call order. Missing unindexed results, reordered prints and duplicate indices remain unpaired, retaining every response. Separate text blocks keep their line boundaries. The outer script's completion state remains separate from child process state.

Replay preserves multi-tool responses even when truncation or running processes leave only one completed result. Indexed results retain their original command slot; rejected results and terminal polls do not shift later command responses. Text that cannot be paired, including retained truncated fragments, remains available in an expandable Output section beneath the activities. A batch's child terminal poll remains a separate expandable activity so its final output can be inspected without replacing the batch response.

User and assistant messages render Markdown by default. System/developer context remains collapsed. Exploration summaries retain a badge for every original call with recorded token usage, even when read filenames are deduplicated; numbered badges follow the original call order, and expansion reveals each command, its tokens and its raw records. Input/cache/output are visible beside total tokens. Cache is included in input, and reasoning is included in output; the tooltip retains exact counts and model. Calls without recorded usage receive no invented estimate. An orchestration call's token badge belongs to the outer call, rather than any individual child result.

Regression coverage shares the reported session's mapped-command and polling records in `e2e/fixtures/mixed-orchestration.json` across Rust replay, frontend projection, React rendering and native WDIO tests. Output events with unknown call IDs never replace a different identified pending call merely because the tool name matches.

`e2e/fixtures/structured-command-responses.json` covers out-of-order parallel prints, stderr, a failed child and a command that completes during a later poll. Rust and native WDIO verify that all three execution IDs belong to the original batch; frontend tests verify that each complete response renders beneath its command and keeps its expansion and raw JSONL provenance.

Exploration classification intentionally accepts only known literal read/search/list commands. Unknown shell syntax, mixed scripts, failed/running/stopped calls and batches remain ordinary activities. Existing batch exit statuses, process polling, signal handling and raw JSONL provenance are preserved. Command summaries show three leading and two trailing lines with the omitted line count; expansion shows all retained output. A replay cannot recover output that was already truncated in the source log.
